1. VLAN, TRUNK И МАРШРУТИЗАЦИЯ
VLAN — отдельный широковещательный домен.
Access — порт одного VLAN. Trunk переносит несколько VLAN по одному кабелю.
802.1Q добавляет метку VLAN; native обычно идёт без метки и должен совпадать на концах trunk.
Allowed list определяет, какие VLAN разрешены на trunk. Он не разрешает связь МЕЖДУ VLAN.
Разные IP-подсети связывает маршрутизатор либо L3-коммутатор.
Router-on-a-stick — один физический порт R1 и несколько логических подинтерфейсов.
encapsulation dot1Q 20 привязывает подинтерфейс к VLAN 20. Суффикс .20 — удобное имя, а VLAN определяет dot1Q.

2. ЧТО ИМЕННО РАЗРЕШАЕТ ACL
Расширенная ACL: действие → протокол → источник → назначение → дополнительные условия.
permit — разрешить ТОЛЬКО пакет, подходящий под все условия строки.
deny — запретить совпавший пакет.
permit ip — разрешить IPv4-трафик, включая TCP, UDP и ICMP, между указанными адресами.
Правила проверяются сверху вниз до ПЕРВОГО совпадения. Остальные строки после него не проверяются.
В конце есть неявный запрет. Явный deny ip any any удобен для счётчиков.
В any any первое any — источник, второе — назначение.

Пример:
permit ip 192.168.30.0 0.0.0.255 192.168.20.0 0.0.0.255
Откуда: продажи .30.0/24. Куда: IT .20.0/24. Что: любой IPv4-трафик.

Wildcard 0.0.0.255 для /24: первые три октета проверять, последний игнорировать.
В wildcard бит 0 означает «проверять», бит 1 — «не учитывать».
host 192.168.40.1 — ровно один IP (эквивалент wildcard 0.0.0.0).

3. ICMP
ICMP — протокол служебных сообщений и диагностики IP-сети. Передаётся внутри IP.
Echo Request — запрос ping; Echo Reply — ответ.
Destination Unreachable — сообщение о недоступности.
Time Exceeded — истёк TTL пакета; используется трассировкой.
ICMP не использует TCP/UDP-порты.

permit icmp 192.168.40.0 0.0.0.255 host 192.168.40.1 echo
Разрешает гостям только ЗАПРОС ping своего шлюза. echo — тип ICMP.
Успешный ping не доказывает работу SSH или сайта. Заблокированный ping не доказывает, что устройство выключено.

4. СОЗДАТЬ СПИСОК И ПРИМЕНИТЬ ЕГО — ДВА ДЕЙСТВИЯ
ip access-list extended GUEST_IN
 permit icmp 192.168.40.0 0.0.0.255 host 192.168.40.1 echo
 deny ip any any
exit
interface gigabitEthernet0/0.40
 ip access-group GUEST_IN in

in — вход в РОУТЕР из VLAN 40. out — выход из роутера через этот интерфейс.
Имя ACL произвольное; место применения задаёт ip access-group.
Созданный, но не применённый список этот поток не фильтрует.

5. ОБРАТНЫЕ ПАКЕТЫ
Обычная ACL не запоминает соединения. Каждый пакет проверяется отдельно.
Запрос IT → S1: источник 192.168.20.11, назначение 192.168.99.2; проверяет IT_IN.
Ответ S1 → IT: источник 192.168.99.2, назначение 192.168.20.11; проверяет MANAGEMENT_IN.
При фильтрации с обеих сторон нужны разрешения обоих направлений.
Без ACL отдельно открывать ответ не требуется: нужны рабочая маршрутизация и отсутствие других запретов.
Наш permit ip разрешает и ответы, и новые обращения между разрешёнными сетями.

6. УПРАВЛЕНИЕ КОММУТАТОРОМ
interface vlan 99 — SVI, виртуальный интерфейс самого коммутатора.
S1: 192.168.99.2/24. S2: 192.168.99.3/24.
ip default-gateway 192.168.99.1 — шлюз для собственного IP-трафика L2-коммутатора в другие сети.
Доступ К свитчу по IP и передача кадров ЧЕРЕЗ свитч — разные вещи.
Запрет доступа к SVI не мешает коммутатору передавать разрешённый пользовательский трафик.
Внутри одной VLAN ПК общаются через S1/S2 без R1 — его ACL такой обмен не проверяют.

7. ПРОВЕРКИ
show vlan brief — VLAN и access-порты.
show interfaces trunk — trunk, native, allowed и передаваемые VLAN.
show ip interface brief — адреса и состояния интерфейсов.
show ip route — C: подключённая сеть; L: собственный адрес роутера /32.
show access-lists — правила и matches, число совпавших пакетов (не соединений).
show ip interface gigabitEthernet0/0.20 — привязка входящей/исходящей ACL к интерфейсу.
show running-config — текущие настройки.
ping — доступность по ICMP. На Cisco ! — ответ, U — недоступность, точка — тайм-аут.
tracert 192.168.10.11 — на ПК. traceroute — на Cisco.
Наш tracert из IT: 192.168.20.1 → 192.168.10.11.
L2-свитчи не показываются отдельными шагами: они не уменьшают TTL IP-пакета.
Первый тайм-аут может быть из-за ARP; постоянные потери нельзя списывать на ARP без проверки.
Проверяем и разрешения, и запреты. Сначала рабочая сеть, потом ACL.

8. СОХРАНЕНИЕ И ЭКСПОРТ
copy running-config startup-config — сохранить работающую конфигурацию для загрузки устройства.
Ctrl+S — сохранить .pkt в Packet Tracer.
Устройство → Config → GLOBAL → Settings → Running Config → Export.
Экспортируем R1_config.txt, S1_config.txt, S2_config.txt. Вручную копировать show run не обязательно.
Экспорт TXT не заменяет сохранение startup-config и .pkt.

9. НАША ФАКТИЧЕСКАЯ СХЕМА
R1 G0/0 ↔ S1 Fa0/1. S1 Fa0/6 ↔ S2 Fa0/1.
На обоих свитчах: Fa0/2 бухгалтерия, Fa0/3 IT, Fa0/4 продажи, Fa0/5 гости.
VLAN 10/20/30/40 — отделы; 99 — управление; 999 — native без IP.
Сети 192.168.<VLAN>.0/24; шлюз .1; ПК на S1 .11, на S2 .12.
IT ↔ бухгалтерия / продажи / управление разрешены. Другие межвлановые пары запрещены.
Гости могут общаться внутри своего VLAN и пинговать свой шлюз.
Интернет, NAT, DHCP и IPv6 в П2 не настраивали. SSH в выполненных шагах не подтверждён.

Комплект сдачи: .pkt, подписанная схема, техдок, полные экспорты R1/S1/S2.
Этот конспект объясняет изученное и не заменяет полные конфигурации устройств.
